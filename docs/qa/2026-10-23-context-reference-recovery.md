# Context, reference and recovery fixes - 23 October 2026

This change addresses seven findings from a private browser exercise. No case documents or captured legal text belong in this report or the repository.

## Behavior

- Context capacity counts the canonical source representation once, preserving selected passages, original paragraph locators and all authorized history. The 240,000-character runtime guard remains. Preflight adds an explicit planned-history estimate and reports headroom; it is not a guarantee of completion.
- Terminal owner audits expose saved preliminary ballot reasons and profiles. Failed runs display their actual error and unavailable turns, with preliminary counts distinct from final verdicts. Context/configuration failures require reviewed new settings; transient recovery remains available.
- Source-use settings support an explicit active permitted purpose per source. Unknown, prohibited and unlisted purposes still fail closed. Preflight rejects unresolved purpose restrictions before saving a proceeding or dispatching a call. The selected purpose is additive versioned ledger JSON, so earlier archives remain compatible.
- Generated page references are checked against canonical supplied-file extraction pages. Printed original-report pagination is not assumed to equal selected-file pagination. Repair feedback requests a verified supplied paragraph instead of guessed folios.
- Approved element instructions and their burdens are supplied to both generation and semantic checking, and retained during repairs. Closed-model author instructions prohibit adding, removing or replacing approved elements. A deterministic guard also covers the observed invented investor-reliance requirement when absent from the controlling model; it does not declare governing law or certify all legal propositions.
- A mixed instruction-threshold/source-transaction statement no longer incorrectly requires the approved threshold in a bank quotation. Instruction and proposed-count amounts must match the approved threshold and currency; adjacent factual amounts still require their own support. Operative-charge claims are not established by an exercise instruction. Independent source-support and ballot-consistency failures remain enforced.
- An explicitly introduced quotation of the exact current approved element also identifies its threshold as setup. Only that quoted amount is separated from factual amounts; adjacent payments and independent semantic rejections remain checked.
- Preserved PDF pages render locally as bounded images from SHA-256-verified original bytes, with previous/next navigation and the original download. This avoids dependency on an embedded browser PDF plugin. No new dependency or external rendering service is used.

Mixed source-backed payment analysis requires an explicit source support domain and verified citations; a blanket analysis label cannot bypass amount or semantic checks. Author and checker prompts separate attributed source figures from conditional value arguments, keep unknown currency visible, and retain the approved closed element list through repairs.

Editing permitted or prohibited purposes clears an active purpose that is no longer selectable. Other source restrictions are preserved, and conflicting permitted/prohibited lists still require correction before the source can be used.

Purpose fields preserve typed newlines while saving normalized lists. Transient provider resource errors remain resumable. Local denials of an extra reliance requirement do not hide a separate affirmative requirement, and approved count thresholds support the observed fronted or trailing burden wording.

A conditional argument that an appropriately linked recorded figure could support the approved value element does not require the threshold in a transaction quotation. The condition does not establish the link or override a separate semantic rejection.

The same approved comparison recognizes hyphenated proposed-count captions, embedded party submissions and evidence-standard wording. Actual filed-charge amounts still require source support; an exercise model cannot supply them.

## Regression and replay coverage

New regressions cover duplicate source representations and full history, projected headroom and runtime overflow, explicit allowed/denied source purposes, terminal audit access, initial-versus-final counts, legacy preflight responses, real two-page PDF rasterization and hash/boundary failures, invalid supplied-page references, added elements and mixed threshold amounts. Captured failures are replayed privately, with fictional controls committed as regression source. A rejected contradictory ballot remains rejected even after correcting a separate false diagnostic.

## Validation

The complete project checks and a fresh bounded visible-browser exercise are recorded separately in the private run report. Deterministic checks do not establish the quality of a live synthetic decision, legal readiness or predictive accuracy. Historical outputs and failed-run records are preserved.
